# PASS 网页原型

PASS 是一款在 8×10 棋盘上进行的足球卡牌策略游戏。本仓库同时包含单机人机对战、Windows 便携版和网页联机测试版。

## 当前实现

- 固定交替回合顺序：R1、B1、R2、B2、R3、B3。
- 棋盘两端 D、E 线外各有两个球门格，只有射门入门才能得分；率先取得 3 球获胜。
- 当前平衡测试牌库为 39 张：Rock、Bishop、Knight 各 13 张；特殊卡暂时全部停用，但实现予以保留。
- 每回合自动抽 1 张；随后在准备阶段，无球队员获得 2 点行动力，持球者获得 1 点。
- 卡牌右上角标出行动力费用，当前同时存在 0 费与 1 费卡。
- 防守方可以弃置一张普通牌，对邻近的对方持球者上抢。
- 棋盘上方会即时显示最近一次行动，路径、目标和球权变化也会短暂高亮。
- Rock 横纵传球最多 6 格，Bishop 斜向传球最多 4 格；Knight 仍为一次标准折线路线。
- AI 按局面收益加权随机选择，不会每局执行完全相同的行动。

完整规则见 [RULES.md](./RULES.md)。

## 配置并启动游戏

单机人机对战不需要网页服务器或账号系统。

需要 Node.js 22.13 或更高版本和 pnpm。可以在 GitHub 点击 **Code → Download ZIP**，也可以运行：

```text
git clone https://github.com/logic2c/pass-tactical-football.git
cd pass-tactical-football
pnpm install
pnpm dev
```

在浏览器打开终端显示的地址，通常是 `http://localhost:3000`。生产构建可以使用：

```text
pnpm build
pnpm start
```

## 网页联机版

联机版采用“网页界面 + WebSocket 比赛服务器”的结构。`server/` 是比赛服务器源码，不是控制远端机器的脚本；远端部署可以使用托管平台控制台或 GitHub Actions，不要求在项目根目录堆放运维脚本。

本地双人测试时，先启动比赛服务器：

```text
cd server
npm install
npm start
```

随后在另一个终端启动网页，并通过 `?multiplayer=1` 进入联机入口。默认本地比赛服务器地址为 `ws://localhost:8080`；正式网页部署时应将 `NEXT_PUBLIC_WS_URL` 设置为公开的 `wss://` 地址。网页与服务器可以分别部署，反向代理到同域 `/ws` 也可以。

联机版当前具备：

- 1v1、2v2、传统 3v3 和传统 4v4 房间，并支持空位 AI 补位。
- “3v3 双人整队”：仅需两名真人，每人控制一整队三名球员。
- “4v4 四人搭档”：每队两名真人，分别控制 1/3 号与 2/4 号球员。
- 多球员控制模式下，玩家只能查看自己控制球员的手牌；足球持有者仍始终公开。
- 每个真人玩家独立的蓝/红方棋盘视角。
- 昵称同步到棋子、行动提示和比赛记录。
- 秘密重连凭证、自动重试及页面刷新后的会话恢复。
- 服务端权威校验；其他玩家不能读取真实手牌与牌库顺序。
- 进球后重新布阵，由下一名接球队员确认开球。

## 游戏内配置

1. 开始时选择红队或蓝队；你控制己方全部 3 名球员，对方全部由 AI 控制，开赛后不能换队。
2. 选择任意己方球员，再点击己方半场空格调整位置。
3. 点击“开始比赛”。进球后可以再次调整自己的位置并确认开球。
4. 顶部黄色标记显示当前球员，球员旁的 `●` 表示公开持球者。
5. 棋盘上方的行动提示会显示谁做了什么以及公开结果，无需反复翻阅比赛记录。
6. 足球传到空格后会单独显示，直到某名球员合法移动经过该格；直接传给队友则立即由队友持球。

## 每回合怎样操作

回合开始自动抽 1 张，随后进入准备阶段并获得行动力。尚未行动时可以点击“战术整备”，跳过出牌并额外抽 2 张。

- 无球队员获得 2 点行动力，持球者获得 1 点；飞踢减益在准备阶段结算。
- **MOVE**：选择移动卡和 MOVE，再点击高亮位置，支付卡面费用 1。
- **PASS**：只有持球者可用。选择移动卡和 PASS，再点击合法空格或队友；扑救响应结算后进入弃牌阶段。
- **PRESS**：防守方选择并弃置自己一张非足球牌，对一格以内的对方持球者上抢。随机抽中普通牌则弃掉该牌，抽中足球则夺得球权；只要仍有行动力和费用牌便可重复使用。
- **TACKLE**：双方均可使用；选择一格以内的对手并随机抢走一张牌，每回合最多一次。
- **冲刺（0）**：本回合获得 1 点额外行动力。
- **补给（1）**：抽 2 张牌，抽到的牌可以立即使用。
- **长传（0）**：令本回合下一次 Pass 可以越过第一名球员，但不能越过第二名球员，也不能射门。
- **扑救**：防守方在对手宣布 Pass 后响应；弃 X 张额外牌移动 X 步。进攻方可 0 费弃置扑救并抽 1 张。
- **飞踢（1）**：对“一步”内的对手使用，使其下回合行动力 −1；若其持球则直接夺球。
- **结束出牌**：保留当前状态，直接进入弃牌阶段。

回合中途获得足球不会重置行动次数：第一次行动拿到球通常还剩 1 次，可移动或传球；第二次行动拿到球时剩余 0 次，不能继续行动。下一回合若仍持球，则以持球者的 1 次行动开始。

## 路线规则

- Rock：横纵 Move 最多 3 格；Pass 最多 6 格。
- Bishop：斜线 Move 最多 2 格；Pass 最多 4 格。
- Knight：使用一次标准折线（国际象棋“日”字）移动或传球。
- Move 不能穿过队友或对手；Knight 的第一格也不能被占据。
- Pass 路线会被任何球员阻挡；最先挡路的队友可以作为直接接球目标，对手不能成为传球目标。
- Knight 的第一格路线若是队友，可直接把球传给该队友；若是对手，则后续落点均被阻挡。
- “一步”仅指横向或纵向相邻；“一格”包括横向、纵向和斜向相邻。
- 当前测试牌库不生成特殊卡；特殊卡条目仅保留为未来恢复时的规则资料。
- 移动合法经过落地足球时会拾球；足球本身不会阻挡路线。
- 球员不能移动进球门。射门目标可以是对方任意一个场外球门格，但射门者位于对方禁区时不能射门。
- 棋盘纵轴依次为 `1–9、X`，所以每个格子仍保持两个字符，例如 `d5`、`eX`；未来继续扩展时依次使用 `Y、Z、A–W`。
- `c1–f1` 与 `cX–fX` 是两端禁区。防守方本方禁区最多 1 人；球权转换造成的暂时超员，在身处禁区的本方球员回合结束时判罚并重新开球。

## 手牌与隐藏信息

- 进攻方行动卡与特殊卡上限为 5，防守方为 6，只在自己的弃牌阶段检查。
- 足球不计入上限且不能弃置。
- AI 手牌以牌背显示，足球具体位于哪张未知牌不会公开，但持球者始终公开。

## 行动轨迹

- 每次 Move 用实线箭头表示；同一回合移动两次会保留两道箭头。
- Pass 用虚线箭头表示。
- 扑救移动使用独立的黄色响应轨迹，不会覆盖球员自己的回合记录。
- 每名球员的轨迹保留到其下次回合开始；进球重新布阵时清空全部旧轨迹。

## Windows 单机版

单机版与网页版共用规则和 AI，不需要账号、服务器、Node.js 或 GitHub 配置。玩家下载 `PASS-0.1.0-Windows.exe` 后直接双击即可游玩，按 `F1` 可打开内置文字教程。

开发者运行 `pnpm desktop:dist` 可在 `release/` 生成新的 Windows 便携版。桌面打包说明和未来联机结构见 [DESKTOP.md](./DESKTOP.md)，独立文字教程见 [TUTORIAL.md](./TUTORIAL.md)。
