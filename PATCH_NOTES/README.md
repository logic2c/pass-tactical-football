# PASS 版本更新记录

本目录用于保存 PASS 从当前成熟测试版开始的规则、平衡性与玩法更新，形式参考长期运营游戏的版本公告。

## 记录原则

- 一个正式版本对应一个独立 Markdown 文件，文件名使用 `v主版本.次版本.修订版本.md`。
- 每项调整同时记录“调整前”“调整后”和“设计原因”，不得只保留最终数值。
- 尚在讨论、未进入游戏的内容统一写入 `NEXT.md`，不提前视为正式规则。
- 实现完成后补充影响范围、代码状态和测试结果；发布后可继续补充实战观察。
- 如果一项方案被取消，也保留记录并标记为“未采用”，避免以后重复讨论。

## 版本编号建议

- **主版本**：核心玩法、胜利条件或游戏结构发生根本变化。
- **次版本**：一组正式的规则、卡牌或平衡性调整。
- **修订版本**：不改变设计意图的数值微调、漏洞修复和表述修正。

## 推荐流程

1. 将玩家提出的调整及理由逐条写入 `NEXT.md`。
2. 确认规则歧义、边界情况和关联影响。
3. 用户明确要求开始实现后，再修改游戏代码与正式规则文档。
4. 完成构建、自动测试和实际试玩检查。
5. 将 `NEXT.md` 整理为正式版本文件，并重新创建空白草案。
